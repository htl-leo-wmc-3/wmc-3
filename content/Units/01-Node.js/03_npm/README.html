4.1 What is npm?

  • Formally called Node Package Manager
  • Consists of three components:
    • website
      • description of available packages
    • registry
      • contains all packages
    • client app
      • Command Line Interface (CLI) for managing packages
      • automatically installed with Node.js

4.2 What do you do with npm?

  • Manage your project
    • author, version number, license, …
  • Manage your project dependencies
    • install / uninstall / update packages
  • Publish your own project to the npm registry

4.3 Project dependencies

The following problems have to be solved in every project that depends on libraries:

  • How do we define which dependencies the application needs?
  • How do we know if dependencies should be updated?
  • How do we reinstall dependencies on another machine?

npm solves those problems with the file package.json.

4.4 Create a package.json

  • Open the project directory in your terminal.

  • Run the following command:

    $ npm init

  • As a result, a file called package.json will be created:

    {
  "name": "npm-demo",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "John Snow",
  "license": "ISC"
}

4.5 Install the chalk package

  • chalk is a package for formatting your console output.

  • You can install it via npm:

    $ npm install chalk

:bulb: The exact version depends on the current npm registry. At the time this material was updated, the latest release is 6.0.0, so the version shown below may differ slightly in your environment.

  • You can check the installed chalk version:

    $ npm list
> npm-demo@1.0.0 /home/mh/node/npm-demo
> └── chalk@6.0.0

  • You will also find a new dependency in package.json:

    {
  "name": "npm-demo",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "type": "module",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "John Snow",
  "license": "ISC",
  "dependencies": {
    "chalk": "^6.0.0"
  }
}

4.6 Semantic versioning

  • Version number format: MAJOR.MINOR.PATCH
  • 6.0.0 means
    • MAJOR = 6
    • MINOR = 0
    • PATCH = 0
  • Increment:
    • MAJOR when you make incompatible API changes
    • MINOR when you add functionality in a backwards compatible way
    • PATCH when you make backwards compatible bug fixes
  • More details: semver.org

4.7 Versions in package.json

  • 6.0.0 means
    • install exactly version 6.0.0
  • ~6.0.0 means
    • install the most recent 6.0.x version
  • ^6.0.0 means
    • install the most recent 6.x.x version

4.8 Install a specific chalk version and update

  • You can uninstall chalk via npm:

    $ npm uninstall chalk

  • You can install a specific version (for example version 5.1.0):

    $ npm install chalk@5.1.0

  • After that, you can update to a later version within the same major release:

    $ npm update chalk

  • This would update chalk to version 5.6.2 as of today

    • by changing the node_modules and package-lock.json
    • while respecting the restrictions in package.json

4.9 Import the installed chalk package

  • Make sure the type is set to module in your package.json file.
"type": "module"

  • Create a file index.js with the following content:

    import chalk from "chalk";

console.log(chalk.red("Hello world"));

  • Afterwards execute the program:

    $ node index.js

4.10 Install and execute the cowsay package

  • cowsay is a package for showing a configurable talking cow.

  • npm install cowsay

    • installs the package to node_modules/cowsay
    • installs the executable to node_modules/.bin

  • You can execute it with the following command:

    $ ./node_modules/.bin/cowsay "Hello world!"

  • An easier way is to use npx:

    $ npx cowsay "Hello world!"

4.11 What is in node_modules?

  • All packages are installed in a folder called node_modules

    • … and their dependencies
    • … and the dependencies of the dependencies …

  • You can take a look at all installed packages:

    $ npm list --all

  • node_modules can contain a lot of files

    • don’t copy it from machine to machine
    • never (!!!) add it to a Git repository

4.12 Git ignore node_modules

  • Create a file called .gitignore in your Git repository.

    • the file must be named exactly like that
    • do not call it something like .gitignore.txt

  • Add the following line to .gitignore:

    node_modules/

4.13 package-lock.json

  • npm install also creates the file package-lock.json.

  • The exact versions that were downloaded into node_modules are written to package-lock.json.

  • Add package-lock.json to your Git repository.

  • After that, your teammates can pull the repo and call npm install.

    • they will get the same package versions as you
    • even if a newer version is already available

4.14 Common problems

  • node or npm is not recognized:
    • check whether Node.js is installed correctly
    • restart the terminal after installation
  • Cannot find module:
    • check whether the package was installed with npm install
    • check whether the project uses the correct package.json
  • SyntaxError: Cannot use import statement outside a module:
    • add "type": "module" to package.json
